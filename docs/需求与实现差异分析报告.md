## 1. 文档中有但代码中未实现的功能

### 1.1 ForceDefaultLanguageMiddleware

| 项目 | 内容 |
| ---- | ---- |
| **文档出处** | 需求文档 §20.2 `[locale] force = True` 配置项；settings.py 中引用 |
| **预期行为** | 当 `[locale] force = True` 时，加载 `ForceDefaultLanguageMiddleware` 忽略浏览器语言头，强制使用配置的默认语言 |
| **现状** | `backend/apps/admin/middleware/language.py` 文件不存在。settings.py 中引用了此中间件，但源文件缺失。启用 `force=True` 会触发 `ImportError` |
| **影响范围** | 中。当前默认值 `force=False`，不影响正常使用。开启强制语言时会报错 |
| **建议** | 创建 `backend/apps/admin/middleware/language.py`，实现 `ForceDefaultLanguageMiddleware`（可参考 Django `LocaleMiddleware` 源码修改） |

### 1.2 通知渠道 Stub（钉钉/OA/WebHook）

| 项目 | 内容 |
| ---- | ---- |
| **文档出处** | 需求文档 §9.5（通用统一通知接口）、§18.5（健康监控-通知渠道维度） |
| **预期行为** | `DingTalkChannel` 通过钉钉机器人发送通知，`OAChannel` 发送到企业内部 OA，`WebhookChannel` 发送到配置的 Webhook URL |
| **现状** | `notification_channels.py` 中三个渠道均为 **Stub 桩实现**：`send()` 仅打印日志并返回 `False`，不实际发送消息 |
| **影响范围** | 中。站内和邮件渠道正常工作，企业微信渠道完整。仅钉钉/OA/WebHook 渠道不可用 |
| **建议** | 1. 短期：文档标注为"预留"状态 2. 中期：实现钉钉机器人消息推送（参考企微实现） |

## 2. 文档中有但代码实现不完整或存在差异的功能

### 2.1 回收站恢复（批量操作）

| 项目 | 内容 |
| ---- | ---- |
| **文档出处** | 需求文档 §6.7 回收站管理；UI 设计文档 §6.8 |
| **预期行为** | 支持单个和批量恢复已删除文档，UI 中有"恢复选中"按钮（带 checkbox 多选） |
| **现状** | 后端 `/documents/restore/` 视图仅接受单一 `doc_id` 参数，不支持批量恢复。前端 UI 中批量操作功能调用会失败 |
| **差异** | UI 设计文档明确展示了批量选中 + 恢复的交互，但后端未实现批量接口 |
| **建议** | 扩展 `restore_deleted_document()` 视图，支持 `doc_ids` 列表参数 |

### 2.2 通知渠道配置 — 钉钉/企业微信联动

| 项目 | 内容 |
| ---- | ---- |
| **文档出处** | 需求文档 §9.1（通知类型与默认渠道表）；UI 设计文档 §9.4（绑定后渠道联动） |
| **预期行为** | 绑定企业微信/钉钉后，对应通知设置中的渠道开关自动开启；解绑后自动关闭并置灰 |
| **现状** | 绑定/解绑企业微信的后端逻辑存在，但通知设置中的渠道联动仅实现了企业微信。钉钉的绑定联动因钉钉渠道为 stub 而无效 |
| **差异** | 企微部分完整，钉钉部分未实现 |
| **建议** | 实现钉钉通知渠道后方可联动 |

### 2.3 欢迎通知 — 企业微信补推

| 项目 | 内容 |
| ---- | ---- |
| **文档出处** | 需求文档 §2.3（注册后触发欢迎通知）；需求文档 §9.1（欢迎通知说明） |
| **预期行为** | 用户注册时若未绑定企微，后续绑定后自动补推欢迎通知和历史系统通知到企微 |
| **现状** | 注册时创建 `Notification` 记录（站内+邮件），但绑定企微后的补推逻辑未实现 |
| **差异** | 文档描述了绑定后补推的完整流程，代码中缺少补推触发点 |
| **建议** | 在绑定回调中增加检查，查询用户所有未读通知并通过企微渠道推送 |

### 2.4 文档拖拽排序 — 间隙重排阈值

| 项目 | 内容 |
| ---- | ---- |
| **文档出处** | 需求文档 §6.5（排序值策略：相邻间隙 < 10 时触发全量重排） |
| **预期行为** | 相邻文档 sort 值间隙小于 10 时，自动触发全量重排 |
| **现状** | `DocService.move()` 中实现了间隙插入策略和 `_rebalance_siblings()` 重排方法，但**未检查具体间隙阈值**。重排仅在调用方显式请求时触发 |
| **差异** | 文档明确了"相邻间隙 < 10"的自动重排条件，但代码中的重排逻辑缺少此触发条件 |
| **建议** | 在 `move()` 方法中增加间隙检测逻辑：计算相邻文档 `sort` 值差值，若 < 10 则自动调用 `_rebalance_siblings()` |

## 3. 需求文档与 UI 设计文档之间的差异

### 3.1 文档编辑器模式（需求 §6.3 vs UI §7）

| 差异项 | 需求文档 | UI 设计文档 |
| ------ | -------- | ---------- |
| 编辑器模式编号 | 0=Vditor, 1=电子表格 | 2=Vditor, 3=iceEditor, 4=电子表格 |
| 编辑器数量 | 3 种（Vditor/Luckysheet + 说明 1 废弃） | 3 种（Vditor/iceEditor/Luckysheet） |

**说明**：需求文档的编号仅为 0 和 1，UI 设计文档的编号为 2、3、4，实际上代码中使用的是 2、3、4（模式 0、1 已废弃）。需统一。

| 差异项 | 需求文档 | UI 设计文档 |

**说明**：需求文档有 `welcome` 类型，UI 设计文档 §14.4 的通知类型表中未包含 `welcome`。UI 文档 §14.5 单独描述了欢迎通知专属样式，但应在类型表中补充。

### 3.3 个人中心功能子页（需求 §2.4 vs UI §9.3）

| 差异项 | 需求文档 | UI 设计文档 |
| ------ | -------- | ---------- |
| 功能子页 | 10 个 | 12 个 |
| 缺失项 | 无站内通知、授权申请、图片管理、附件管理、分享管理、API Token 子页 | 已更新 |

**说明**：需求文档更新后已补全大部分，但需确认与 UI 设计文档一致。
