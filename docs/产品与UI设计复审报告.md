### 1.2 表格列宽拖拽调整

**产品评审：⚠️ 条件通过（重大遗留问题）**

| 维度 | 评价 |
|------|------|
| 需求合理性 | 列宽调整是表格操作的刚需，方向正确 |
| ❌ 持久化未实现 | **UI 设计文档明确要求列宽通过 `<!-- column_widths -->` 注释或 `<col style="width:Npx">` 持久化，但代码仅保存在内存中，页面刷新即丢失。** 这意味着用户每次查看文档都要重新调整列宽，体验极差 |
| 最小宽度 40px | 对于中文字段可能偏窄（"操作"2 字约 28px 勉强够，但"备注说明"4 字需 ~56px），建议改为 60px |

**UI 评审：⚠️ 条件通过**

| 维度 | 评价 |
|------|------|
| 拖拽手柄 | 设计为 `position:absolute;right:-4px;width:8px` 的透明区域 hover 时显示品牌色，交互符合预期 |
| Tooltip 显示像素值 | 对普通用户不够友好（"120px" 无意义），建议改为相对描述（"较窄/适中/较宽"）或同时显示百分比 |
| 光标准确性 | `col-resize` 光标仅在悬停透明手柄区域时触发，对用户的视觉提示不足，建议列边框整体可 hover |
| **与 Vditor 编辑器的冲突** | 列宽调整会影响 Vditor 的 Markdown 源码解析，需确认 Vditor IR 模式下列宽调整后保存不会破坏表格结构 |

### 1.4 代码块自动格式化

**产品评审：⚠️ 条件通过**

| 维度 | 评价 |
|------|------|
| 需求合理性 | 代码格式化是技术文档编写的常见需求，方向正确 |
| ❌ 可发现性严重不足 | **仅支持 Ctrl+Shift+F 快捷键，无工具栏按钮、无右键菜单入口**。普通用户几乎不可能发现此功能 |
| 格式化能力有限 | LANG_MAP 覆盖了 20+ 语言，但实际只有 JSON（标准缩排）和 Python（autopep8）有真正的格式化器。其余语言走通用 dedent，效果非常基础，用户期望与实际落差大 |
| 格式化后的 Markdown 源码一致性 | Vditor IR 模式下，格式化代码块后可能触发 Vditor 的重新渲染，需验证格式化的代码在保存后不会丢失变更 |

**UI 评审：❌ 不通过**

| 维度 | 评价 |
|------|------|
| 缺失工具栏按钮 | 应参考"思维导图/流程图/手绘图"的模式，在编辑器工具栏增加"格式化代码"按钮 |
| 缺失右键菜单 | 代码块区域右键菜单应有"格式化代码"选项，这是最自然的触发方式 |
| 边框动画反馈 | 仅在格式过程中改变 `box-shadow`，且使用 CSS 变量引用，但 `pre` 元素的默认样式可能无 `box-shadow` 属性，动画不可见 |
| 成功/失败反馈 | 使用 Toast 提示，但格式化的 Toast 与编辑器自动保存的 Toast 可能混淆，建议使用内联状态提示 |

## 二、横向设计系统一致性问题

### 2.1 Toast 系统碎片化

现在项目中存在 **3 套 Toast 实现**：

| 位置 | 实现 | 样式源 |
|------|------|--------|
| 主站前端 | `iSpaceDoc.Toast` | Design System Token ✅ |
| 管理后台（LayUI 页面） | `layer.msg()` | LayUI 主题 ⚠️ |
| 管理后台（本次改动回退） | 内联 div 硬编码颜色 | 无主题 ❌ |

建议统一：管理后台也应引入 Design System 的 Toast 组件，或扩展现有组件覆盖 admin 场景。

### 2.2 代码块交互入口不一致

| 功能 | 工具栏按钮 | 右键菜单 | 快捷键 |
|------|-----------|---------|--------|
| 思维导图 | ✅ | ❌ | ❌ |
| 流程图 | ✅ | ❌ | ❌ |
| 子文档目录 | ✅ | ❌ | ❌ |
| 代码格式化 | ❌ | ❌ | ✅（仅 Ctrl+Shift+F） |

产品建议：代码格式化应增加工具栏按钮入口以保持一致。

### 2.3 图标风格不统一

子文档目录组件使用了 SVG outline 图标（`<svg stroke="currentColor">`），而系统现有文档树侧边栏使用 emoji（`📄`）和 LayUI 图标字体。两者视觉风格不同会导致用户感知不一致。

## 三、交互设计完整性问题

### 3.1 列宽持久化缺失（P0 级需修复）

**严重性**：高。用户拖拽调整列宽后刷新页面即丢失，产品体验严重受损。

**建议方案**：
- 视图页：通过 AJAX 保存列宽到 `Doc.content_json` 或新增 `Doc.table_column_widths` 字段
- 编辑器内：列宽持久化到 Markdown HTML 注释 `<!-- column_widths: [120,200,80] -->`
- 渲染时：检测 Markdown 注释或 `column_widths` 字段 → 自动应用列宽

### 3.2 代码格式化可发现性缺失

**严重性**：中。功能存在但用户无法发现。

**建议方案**：
- 编辑器工具栏新增"格式化代码"按钮（在"代码块"相关按钮组内）
- 代码块右键菜单增加"格式化代码"选项
- 粘贴代码时自动检测并询问是否格式化（可选）

### 3.3 子文档目录编辑态预览缺失

**严重性**：低。编辑器占位符可用，但缺乏所见即所得的编辑体验。

**建议**：在 Vditor 渲染器中注册 ```` ```child-doc-list ```` 的客户端预览，在编辑模式下显示简化版子文档列表。
