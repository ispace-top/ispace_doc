## QA 分析结果

45 个测试中 13 个未通过，分 4 类：

### 分类 A: PermissionAPI/SecurityAPI setUp 变量错误（8 ERROR）

| 测试类 | 行号 | 问题 |
|--------|------|------|
| PermissionAPITests ×5 | L378 | `create_user=self.user` — `self.user` 不存在，应为 `self.admin` |
| SecurityAPITests ×3 | L650 | `create_user=self.user` — `self.user` 不存在，应为 `self.victim` |

**根因**：替换 Project 时误用了 `self.user`（User 中心测试的变量名），但 Permission/Security mixin 使用 `self.admin`/`self.victim`。

**影响范围**：仅限于 setUp 中创建的 Doc 的 create_user 字段值不同，不影响测试逻辑。

### 分类 B: 旧 API 响应格式断言（6 FAIL）

| 行号 | 当前代码 | 问题 |
|------|---------|------|
| L185 | `assertFalse(data.get('status'))` | API 已改用 `code:0` 格式 |
| L239 | `assertTrue(data.get('status'),` | 同上 |
| L348 | `assertFalse(data.get('status'))` | 同上 |
| L392 | `if data.get('status'):` | 条件分支依赖旧格式 |
| L472 | `assertFalse(data.get('status'))` | 同上 |
| L673 | `assertFalse(data.get('status'))` | 同上 |

**根因**：API 统一响应格式从 `{"status": True/False}` 迁移到 `{"code": 0}`，测试未同步更新。

### 分类 C: SQLite 表锁（7 FAIL）

`database table is locked: app_doc_doc` — 测试并行运行时 SQLite 文件锁冲突。

**根因**：测试使用 SQLite 内存数据库，高并发时产生锁竞争。

### 分类 D: 通知 API 断言（1 FAIL）

L586/L589: `assertEqual(data.get('code'), 0)` — 通知 API 返回的 `code` 可能是 `None`，等待进一步确认。
