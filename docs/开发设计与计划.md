## 2. P0 — 阻塞性缺陷（必须修复）

### P0-1 ForceDefaultLanguageMiddleware 文件缺失

| 维度               | 内容                                                                                                                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题**     | `backend/apps/admin/middleware/language.py` 文件不存在。`settings.py` 中引用了 `ForceDefaultLanguageMiddleware`，但源文件从未创建。当 `config.ini` 中 `[locale] force = True` 时触发 `ImportError` |
| **影响范围** | 仅在显式启用 `[locale] force = True` 时报错。当前默认 `force=False`，不影响正常使用                                                                                                                        |
| **根因**     | 代码规划了强制语言中间件但未实际编写                                                                                                                                                                           |

**技术方案**：

创建 `backend/apps/admin/middleware/language.py`：

```python
from django.conf import settings
from django.utils import translation

class ForceDefaultLanguageMiddleware:
    """强制使用配置的默认语言，忽略浏览器 Accept-Language 头"""
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        if settings.LANGUAGE_FORCE:
            language = settings.LANGUAGE_CODE
            translation.activate(language)
            request.LANGUAGE_CODE = language
        response = self.get_response(request)
        return response
```

| 工作量 | 涉及文件                                           |
| ------ | -------------------------------------------------- |
| 0.5h   | 新建 `backend/apps/admin/middleware/language.py` |

### P0-2 回收站恢复不支持批量操作

| 维度               | 内容                                                                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题**     | UI 设计文档 §6.8 展示的回收站页面包含"恢复选中"批量操作（checkbox + 批量按钮），但后端 `/documents/restore/` 视图仅接受单一 `doc_id` 参数 |
| **影响范围** | 回收站页面的批量恢复功能不可用。单篇恢复正常                                                                                                   |
| **根因**     | 后端视图未扩展为适配批量                                                                                                                       |

**技术方案**：

扩展现有 `restore_deleted_document` 视图：

```python
@login_required
def restore_deleted_document(request):
    doc_ids = request.POST.getlist('doc_ids') or [request.POST.get('doc_id')]
    if not doc_ids:
        return JsonResponse({'code': 5, 'msg': '参数不正确'})
    results = []
    for doc_id in doc_ids:
        try:
            DocService.restore(doc_id)  # 已支持级联恢复子文档
            results.append({'doc_id': doc_id, 'success': True})
        except Exception as e:
            results.append({'doc_id': doc_id, 'success': False, 'error': str(e)})
    return JsonResponse({'code': 0, 'data': results})
```

| ------ | ------------------------------------------------------------------ |
| 2h     | `backend/apps/doc/views.py`（修改 `restore_deleted_document`） |

### P1-2 拖拽排序间隙阈值检查

| 维度               | 内容                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| **问题**     | 需求文档 §6.5 指定"相邻间隙 < 10 时触发全量重排"，但 `DocService.move()` 中未实现间隙检测逻辑 |
| **影响范围** | 频繁拖拽排序可能导致 sort 值间隙耗尽，后续插入需手动全量重排                                     |
| **根因**     | 重排方法 `_rebalance_siblings()` 已实现但缺乏自动触发条件                                      |

**技术方案**：

在 `DocService.move()` 中插入间隙检测逻辑：

```python
@staticmethod
def move(doc_id, new_parent_id, position):
    with transaction.atomic():
        # ... 插入逻辑 ...
        siblings = Doc.objects.filter(parent_doc=new_parent_id, is_deleted=False)
        # 检查间隙：计算相邻 sort 值差值
        gaps = []
        sorted_siblings = sorted(siblings, key=lambda d: d.sort)
        for i in range(len(sorted_siblings) - 1):
            gap = sorted_siblings[i+1].sort - sorted_siblings[i].sort
            gaps.append(gap)
        if gaps and min(gaps) < 10:
            DocService._rebalance_siblings(new_parent_id)
```

| ------ | --------------------------------------------------------- |
| 2h     | `backend/apps/doc/services.py`（`DocService.move()`） |

### P1-3 欢迎通知绑定企微后补推

| 维度               | 内容                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| **问题**     | 需求文档 §2.3/§9.1 描述：用户注册时若未绑定企微，后续绑定后自动补推欢迎通知和历史系统通知。此补推逻辑未实现 |
| **影响范围** | 绑定企微的用户收不到注册时的欢迎通知和等待期间的系统通知                                                      |

**技术方案**：

在企微绑定回调（`/auth/wecom/bind/callback/`）中增加补推：

```python
# wecom.py callback 处理中
from backend.apps.doc.notification_channels import ChannelManager
from backend.apps.doc.models import Notification

def _backfill_notifications(user):
    """绑定企微后，补推用户未读通知"""
    unread = Notification.objects.filter(
        recipient=user, is_read=False
    ).exclude(
        notification_type__in=['welcome']  # 欢迎通知单独处理
    )
    channel_mgr = ChannelManager()
    for notification in unread:
        channel_mgr.send(notification, user, channels=['wecom'])
  
    # 欢迎通知特殊处理（使用独立模板）
    welcome = Notification.objects.filter(
        recipient=user, notification_type='welcome'
    ).first()
    if welcome:
        channel_mgr.send(welcome, user, channels=['wecom'])
```
